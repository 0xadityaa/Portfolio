## Thread

In 1913 Britain mined about 292 million tonnes of coal, roughly 4x its 1850s average. Engines had been getting more efficient for generations.

Jevons saw the pattern in 1865: efficiency did not save coal, it made more of it worth burning. Now point that at AI-written code ↓

[image: /images/blog/jevons-coal-output.svg]
---
Jevons wrote it as arithmetic: coal used = number of works x coal per work.

Efficiency shrinks the second term and makes the first one grow. If demand for the work is elastic (elasticity above 1), the total goes up.

It is a bet on how hungry demand is, not a law.
---
Same shape for code. Writing a line got cheap. Owning one did not: someone still reads, tests, patches and deletes it.

Dijkstra, 1988: lines of code are "lines spent", not "lines produced".

GitHub counted 986M commits in 2025, up 25%. (Observational, GitHub says, not causal.)
---
So what gets scarce? Reading. A reviewer reads a diff at human speed, whoever wrote it.

Seneca had the same problem with books: "it is enough to possess only as many books as you can read."

Same rule for code.
---
My bet: the scarce skills are the unglamorous ones. Reading a diff closely. Deleting what is not earning its upkeep. Saying no to what is cheap to build and expensive to keep.

## Substack Note

In 1913 Britain mined about 292 million tonnes of coal, roughly four times its average in the 1850s. Steam engines had been getting more efficient for generations. In 1865 William Stanley Jevons described what that does: it is a confusion of ideas, he wrote, to suppose that using fuel economically means using less of it. Efficiency makes more of the work worth doing.

I think code is on the same path. Writing a line has become cheap. Owning one has not, because somebody still has to read it, test it, patch it and eventually delete it. GitHub counted 986 million commits in 2025, up 25%, and a reviewer still reads a diff at the speed of a person.
